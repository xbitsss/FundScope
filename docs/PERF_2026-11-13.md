## Phase 0 · Baseline and instrumentation

The workspace does not contain the user's desktop SQLite database or an extracted hosted snapshot. `.data/` contains build tooling only, so desktop `initializeRepository`, SQL read, JSON parse/normalize, worker transfer, first-result and persistence timings cannot be honestly reported from this machine. The real device capture is still required. Open the app with `?perf=1`; the diagnostics panel records those operations without sending telemetry anywhere. On web, the existing unlock panel records KDF/decrypt/decode and unlock-to-first-result timing. The app panel records first-result, SQL/IndexedDB reads, normalization, synchronous worker `postMessage` cost, worker index phases/build, query round trip and saves after `recomputeAll`.

The local UI bundle is 14,087 bytes larger because the desktop typed-row adapter is included in the application bundle. This is not a measured startup speedup: no representative SQLite file was available to time. Desktop migration, launch timing and real-device rendering still require the user's actual app/database. The migration backs up `schemes`, validates row counts and commits the schema marker atomically; it retains the legacy table if conversion fails.

The worker transfer now builds the existing columnar buffer from typed SQLite rows without first constructing another complete list of fund objects for serialization. The React-facing lightweight fund records are still materialized for UI state.
