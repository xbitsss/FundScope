| Added application data sources / paid services | — | 0 | AMFI, MFapi, GitHub Pages/Actions, browser storage and workers only |

The 23:30 IST schedule provides a 30-minute buffer after the general 11 PM same-business-day NAV disclosure limit. SEBI specifies next-business-day exceptions for FoFs and certain other schemes, so this timing cannot guarantee every scheme is published in the same run. Using the last observed 10-minute ETL duration as a scenario, three runs would use about 30 runner minutes/day or 900/month (300/month more than two runs). These are not measured future runtimes. `ubuntu-latest` is a standard public-repository runner; GitHub documents standard runners as free for public repositories. The ETL still enforces its 45-minute per-run budget and existing site-size limit. See the official [SEBI Master Circular](https://www.sebi.gov.in/sebi_data/attachdocs/mar-2026/1774024028162.pdf) and [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

Phase 2 adds default-window peer rank/percentile columns, 12-point normalized sparklines, a ciphertext-verified one-index device cache, and an encrypted index delta that can be applied on the unlock worker. The delta retains NAV history in the existing history packs and carries changed index fields only. The service worker now prunes old snapshot files on both normal and explicit revalidation. Applying an update replaces the fund array in place; filter state and table scroll stay in the mounted app.

The synthetic delta apply/fallback and columnar round-trip tests pass. The deployment snapshot has not been regenerated, so delta usefulness, actual downloaded bytes, full Pages size, and post-change ETL duration remain unmeasured. Nothing paid or keyed was introduced.

The current repeat of `node scripts/perf-baseline.mjs` used 14,200 deterministic synthetic funds on Node v24.15.0: index build was 123.7 ms on its first run and 100.0 ms p50 across three runs; optimized search was 1.18 ms p50 / 2.23 ms p95. The capture is saved in [`PERF_2026-11-13-core.json`](PERF_2026-11-13-core.json). These are current synthetic screener-core observations, not a Phase 3 before/after comparison and not a phone, browser-paint, chart, SQLite, or worker-transfer measurement. The workspace still has no local full snapshot, so a full GitHub Pages artifact size is unavailable.

Phase 3 adds a 64-history in-memory LRU with seven-day expiry, shared in-flight history and snapshot-file requests with per-caller abort, cancellation of stale virtual-window prefetches, and a bounded encrypted snapshot-file cache. MFapi concurrency and retry/backoff limits are unchanged. History path ordering remains memory/device cache, encrypted snapshot, then MFapi fallback. Chart history normalization, union-date sorting, extrema scans, and SVG path generation now run in the existing metrics worker. The UI still handles only the small interactive date marker and readout.

Validation used the already-installed local binaries because Corepack's pnpm download is unavailable in this network-restricted environment: TypeScript project build passed, desktop and web Vite production builds passed, and Vitest passed all 243 tests in 31 files. The existing Zod annotation and large main-chunk notices remain build warnings; they did not fail either build. No full ETL refresh, real-device latency run, or publish was performed. No paid service, dependency, key, telemetry, or data source was added.
