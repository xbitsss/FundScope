## Decisions and ambiguity notes

- For multiple selected sub-categories, the peer reference pools the eligible unselected active peers from those categories and takes their median. If the total is below ten, it pools eligible peers in the selected asset classes. Funds marked dormant are excluded; records without an explicit active lifecycle are not counted as peers.
- When the requested split lacks enough observations, the fallback order is peer median, selected median, selected mean, then valid custom values. The engine returns an explicit notice with the effective rule. It does not fill missing thresholds.
- Ties remain assigned to the better side for directed metrics, and to the higher-value side for a no-preference metric. A no-preference axis does not receive Best/Avoid labels.
- Existing saved screens keep their valid metric, direction, split and custom-value settings; removed scope/outlier/log-scale values are discarded. A fresh installation defaults to peer median.
- `peerCount` reports the matching peer set used for the reference calculation, after excluding selected and dormant funds.
