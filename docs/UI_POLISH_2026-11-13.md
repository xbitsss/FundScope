# FundScope UI polish implementation report

Implementation completed: 2026-11-14  
Scope: presentation and interaction polish only. Data fetching, persistence, filter semantics, and scoring rules were not changed.

## Changes

1. **Theme and shortcuts** — Corrected the theme-color metadata for light and dark mode and updates it when the app theme changes. The search hint now shows `⌘ K` on Apple platforms and `Ctrl K` elsewhere. No invalid `scroll-behavior: contain` declarations were present; existing containment uses `overscroll-behavior`.
   Commit: `b4d8e91`.
2. **Typography and design tokens** — Bundled `@fontsource-variable/inter` locally; added a responsive type scale, radii, light/dark shadows, easing, and duration tokens in `tokens.css`; imported `polish.css` last; brought UI font declarations below 11px up to the 11px token; added focus rings, readable headings, and thin scrollbars. Sticky table header cells now use a translucent surface with blur. The top bar has no backdrop blur.
   Commit: `43efe12`.
3. **Drawer and controls** — Added token-based pressed states, touch-hover neutralization, a floating desktop detail drawer, and a mobile bottom sheet. The drawer enters in 420ms and exits in 320ms; reduced-motion mode closes it without animation. Only transform and opacity animate the large drawer.
   Commit: `325ebfa`.
4. **Route transitions** — Navigation uses the View Transitions API with `flushSync`; it skips same-route changes, unsupported browsers, and reduced-motion preferences. The main region fades/slides between routes, with the root transition disabled.
   Commit: `26f4946`.
5. **Loading and refresh feedback** — Replaced the sparse table loading placeholder with 8 comfortable or 10 compact skeleton rows at 48px/36px, with matching mobile card skeletons. Refreshes compare each fund’s previous and new numeric metric values, tinting changed values up or down for 900ms and clearing those classes after 1s. Coverage cards use `content-visibility: auto`. No count-up animation was added.

## Validation

- At each of the five stages, local TypeScript, production-build, and full Vitest checks passed. Final run: `tsc -b --pretty false`, `vite build`, and `vitest run` — **32 files, 247 tests passed**.
- `corepack pnpm check` could not start because Corepack attempted to fetch pnpm from `registry.npmjs.org`, which was unreachable. The locally installed TypeScript, Vite, and Vitest binaries were used for equivalent checks.
- `node scripts/verify-dist.mjs` could not verify a deployable snapshot: `dist/data/manifest.json` is absent from this checkout. The app-only `dist` is **1.23 MiB (1,289,936 bytes)**. The encrypted snapshot is not included in that figure, so the complete hosted site cannot be compared with the 950 MiB limit here.
- The emitted self-hosted Inter subset files total **218,512 bytes (213.4 KiB)**. The browser selects the subsets needed by the glyphs on the page.
- Contrast ratios calculated for the light and dark theme text, muted text, accents, positive/negative colors, and primary buttons were all at least **4.97:1** (WCAG AA for normal text).
- Vite still reports the main JavaScript chunk above its 500 kB warning threshold: **576.91 kB raw / 166.26 kB gzip**. The application build succeeds.

## Visual and performance limits

- A browser screenshot and Chrome Performance trace could not be reliably captured in this run, so no 4× CPU frame-drop, layout-recalculation, or CLS measurements are claimed.
- Safari/WebKit and Tauri WebView2 were not tested. The route transition has a direct-update fallback for browsers without View Transitions support.
- Both light and dark design tokens have been retained; the contrast calculation is not a substitute for a rendered screen-reader or device-level accessibility review.
