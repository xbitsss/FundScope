# FundScope changes · 2 November 2026

## AMFI taxonomy, governance, and filtering

- Made the app's classification story consistent with the S0-first pipeline: AMFI Scheme Master is primary when its category is specific; NAVAll is the fallback; TER and AAUM are corroborating AMFI observations; MFapi is strictly informational history metadata and never votes.
- Replaced the old “schemes held as Other” governance card with a reason-coded Unclassified review queue. Groups show distinct AMFI labels and explicit active, dormant, and unknown-lifecycle counts; rows expose the source category fields. Added CSV export for every unclassified scheme and a copyable review stub that deliberately does not assign a leaf.
- Expanded the conflict table to show S0–S4 and rewrote the fund drawer's provenance view to include each field's rule/source. Risk is labeled “Category-implied, not the scheme's official riskometer.”
- Added a pure review-queue grouping function and Vitest coverage proving reason grouping and active/dormant/unknown lifecycle counts.
- Fixed screener search matching so normalized, partial name/fund-house/category queries retain matching rows; added regression coverage. Fixed checklist selection to distinguish an unrestricted empty selection from checked checkboxes, preserving `[]` means all for filtering while allowing users to narrow filters from the picker.
- Kept the category hierarchy and added phone layout refinements for review groups and the embedded governance tables.

## Ambiguities resolved

- “Active” and “dormant” use taxonomy configuration: a past AMFI closure date makes a scheme dormant; absent a closure date, NAV older than 90 days relative to the latest NAV file date is dormant and is described as “No recent NAV.”
- The risk-band matrix is configurable under `config/taxonomy-tree.json` and represents a category heuristic only. It is not attributed to SEBI or presented as the official riskometer.
- Name-based classification is reserved for AMFI Index/ETF/FoF families whose AMFI category does not specify the underlying. Other unresolved records retain a named reason code.

## Performance and unlock implementation

- Added a worker-driven bitset screener index and retained `src/domain/screener/filters.ts` as the semantic reference. Seeded property coverage compares returned rows, funnel counts, and all facet counts over 500 filter combinations; a separate test covers a 14,200-fund index. History/detail-only changes now avoid rebuilding the screener index.
- Replaced hosted v1 whole-object output with a v2 columnar index (dictionary-encoded text fields, typed numeric columns, Float32 metrics and reason bytes); per-fund detail and NAV packs remain separate. Added v1 read compatibility and content-addressed per-snapshot paths. `verify:dist` now checks detail packs as well as history packs.
- Removed hosted unlock's full-catalogue IndexedDB replace/read from the first-render path. The manifest/index are prefetched, an unlock worker performs PBKDF2, DEK unwrap, AES-GCM, decompression and column decoding, and the app receives initial funds directly.
- Added generated high-entropy passphrases, an ETL/secret-scan entropy gate, a 100k PBKDF2 default (the enforced minimum), v2 KEK/DEK wrapping, a five-failure in-memory cooldown, optional IndexedDB device unlock, session expiry choices, and Lock & clear. Storage failure falls back to the passphrase flow.
- Added a scoped static service worker for manifest revalidation and same-origin asset/snapshot caching. The mobile summary remains a two-row structure and the category checklist is inline rather than a portal.
- The detailed scope and measurement limitations are in `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, and `docs/PERF_2026-11-02.md`.
